## 3. 必读约定（踩过坑，务必遵守）
1. CRLF 陷阱（最高频事故）：本仓 core.autocrlf=false 且行尾符混杂——crates/zbrain-cli/src/lib.rs 是 CRLF，其余 Rust 文件与 docs 多为 LF。Edit 工具会整文件改写行尾符 → git diff --numstat 出现 N/N 即中招。提交前必查 git diff --numstat 每文件 + git ls-files --eol 双保险；异常用 git hash-object 验证内容无损，按 HEAD 原始行尾符逐文件对齐。
2. feat / chore 严格分离：改动不自动 commit；按类型拆提交（feat 代码 / docs roadmap / chore memory）。等用户显式 commit / commit+push。
3. 移植前必须先做「TS 源 vs Rust 现状」对账：git show <删除 commit>^:<path> 取回 TS 源 → grep 关键依赖 → grep Rust 侧同名/近义实现 → 列对账表。KNOWN-GAPS 的 blocked/描述不可全信（曾两次证伪：G76/G74 算法已在 Rust，缺的只是 CLI 出口）。grep 命中必须逐行看上下文（注释/fallback 模型 ID 会假阳性）。
4. WSL 构建范式：原生 cargo 在本机 WSL2（jununfly-WinPC）无；用 wsl -d Ubuntu -u zb -- bash <script>.sh，脚本写 /mnt/c/Users/jununfly/AppData/Local/Temp/*.sh，日志写同目录（别写 /tmp）。cargo 在 $HOME/.cargo/bin，CARGO_TARGET_DIR=/home/zb/.cache/zbrain-target。WSL 增量比 Windows 快一个量级，改 Rust 优先走 WSL。
5. 诚实降级铁律：无 API key / 缺依赖时，命令必须 EXIT1 + 清晰报错，绝不可伪造 PASS 或落伪收据（repair_json 4 策略解析器失败时也返回 Err 而非编造分数）。
6. .git/index.lock 僵尸锁：本环境会反复重建 lock 阻塞 git。绕法 mv 改名（rm 被 safe-delete 拦）。
7. 环境清目录怪象：本机有进程/沙箱会在工具调用间隙清空 docs/plans/（及 temp）。只有 git commit 能跨调用持久化；未提交 worktree 文件可能丢失。重要产物务必及时提交。
