## TS 删除安全性审计（决定删除策略）

- **核心结论**：删除会不会破坏 KNOWN-GAPS / Phase 10-11，完全取决于**删哪批 TS**，不是"删/不删"的二元问题。
- **KNOWN-GAPS 依赖 TS 作 spec**：G4/G5/G13/G23/G26/G29 等的"TS 权威来源"列直接指向具体 TS 文件（src/core/search/hybrid.ts、ai/gateway.ts、ai/recipes/、commands/schema.ts@5d5b404~1 等），是补齐时照抄的规范。这些文件**大部分仍在工作树**（hybrid/expansion/intent-weights/gateway/recipes/queue/attachments 全活），仅 schema.ts 已删但可从 git 5d5b404~1 恢复。
- **Phase 10 eval 源全部还在工作树**：src/core/eval*、cross-modal-eval、claw-test、calibration 都活着——Phase 10 要决定 port 哪些、删哪些，删早了就失去 port 素材。
- **git 兜底**：本仓 TS 全程版本追踪，任何删除都能 `git show <sha>:<path>` 恢复。schema.ts 已验证在 5d5b404 被删、历史可取。所以"删了失去 spec"不成立——只是恢复成本 = 多一步 git 考古 + KNOWN-GAPS 的 commit 锚点必须精确。
- **PRD 删除铁律**（complete-ts-to-rust.md）：删除必须逐 slice 走 Deletion Rule checklist；Replacement implies deletion，但**仅删"已被 Rust 验证替换"的 slice**；未替换/被 KNOWN-GAPS 依赖的不能删。
