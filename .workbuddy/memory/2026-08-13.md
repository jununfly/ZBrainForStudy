## ⚠️ 事故：本地 `.git/refs` 丢失 + 恢复（重要）

**现象**：`git rebase origin/rust-rewrite` 因沙箱缺少交互式编辑器报错（`could not mark as interactive`），随后 `git reset` 报 "not a git repository"。诊断发现 `.git/refs` 目录整个被删（疑似沙箱 safe-delete 在失败 rebase/reset 期间触发），`.git/objects`/`packed-refs`/`HEAD` 完好。`packed-refs` 含全部 ref 值（含 `refs/heads/rust-rewrite = 4ad5291c` 旧快照）。

**双重陷阱（本会话新发现）**：
1. 沙箱对**写文件命令会双重执行**（"⚠️ Sandbox bypassed (escalation-approved)"）——`decide`/`add`/`commit` 类命令跑两次，曾造成重复节点/决策，必须幂等写入 + 事后去重。
2. 目录改名 `zbrain→ZBrain`（NTFS 大小写不敏感）后，重命名后的 cwd 路径串失效，原生 git 报 "not a git repository"；但 `cd /c/workspace/github/jununfly/ZBrain && git ...`（MSYS 翻译路径）可用。

**恢复步骤（已验证）**：
1. `mkdir -p .git/refs/{heads,remotes/origin,tags}` 重建 refs 目录。
2. `git fetch origin rust-rewrite` 刷新远端引用（远端 tip = `df89e23f`，含全部历史 + 3 个 CRLF 治理提交 `d6c395d7/11bac542/df89e23f`）。
3. `git reset --hard df89e23f` —— 本地已损坏，远端才是权威，直接对齐到远端干净态（丢失的仅是被拒的、未合入远端的在途提交）。
4. 在途提交 `d2dcbfcb`（含 R1+R2 决策）已因 refs 丢失变 dangling 并被 GC 回收 → **无法恢复**，按对话历史用 Python 脚本确定性重建 json 全部决策/节点（幂等、保 CRLF），再 render。
5. `git push origin rust-rewrite` → 快进 `df89e23f..1b349350` 成功。

**教训**：
- 沙箱里尽量**避免 `git rebase`**（交互式依赖编辑器，易失败并触发 safe-delete 删 refs）。改用 `git reset --soft` + `git pull --ff-only` 或 `reset --hard <remote-tip-SHA>`。
- 写文件命令（含 roadmap CLI、commit）一律**幂等化**（按 id/q 缺失才补），并准备"从远端 tip 重建"的兜底脚本，因为沙箱可能丢失未推送的本地提交。
- `packed-refs` 在 `refs/` 缺失时会返回陈旧值，诊断时用 `git rev-parse <SHA>` 直接核对 commit 而非依赖 ref 名。
