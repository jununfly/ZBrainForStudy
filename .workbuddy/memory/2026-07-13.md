**关键技术点（经验）：**
1. **prune/get_stats cutoff 用 `&str`（RFC-3339）不用 epoch_ms**：因为比较的是 record 列（updated_at/created_at 是 ISO-8601 TEXT），字典序=时间序，两后端通用。
2. **prune 靠 DB `ON DELETE CASCADE` 清子表**，只 `DELETE minion_jobs`；InMemory 无 FK 手动 `retain` 模拟 CASCADE；`contract_prune_cascades_attachments` 守 `PRAGMA foreign_keys` 不被误关。
3. **get_stats 三方言**：PG 照抄 TS（`FILTER` + `EXTRACT(EPOCH...)*1000`），libsql 用 `SUM(CASE)` + `AVG(julianday差*86400000)`，InMemory 内存聚合 + `chrono::DateTime::parse_from_rfc3339` 算时长。
4. **PG `avg()` 返回 NUMERIC 不是 FLOAT8**：Rust `Option<f64>` decode 报 mismatched types → SQL 里 `(avg(...) FILTER(...))::double precision` 显式 cast 修复。这是 PG mirror 测试再次揪出 SQLite 掩盖问题的实例。
5. **stalled 定义**：`status='active' AND lock_until < now`。测试用**负 lock duration**（`claim_job("t3", -1, ...)`）可靠制造过期锁（沿用 handle_stalled 先例）。

**设计要点：**
1. `reserve_budget` CAS-style：`UPDATE ... WHERE budget_remaining_cents >= amount` 是原子守卫（无显式事务）
2. `ReservationOutcome` 全 `Ok` 变体——预算不足是业务决策非 I/O 错误
3. `log_budget_event` best-effort（失败→`tracing::warn!`，不传播）
4. `halt_budget_subtree` 范围匹配 `budget_owner_job_id`，`inherit_budget_owner` 只在有预算时生效（`WHERE budget_owner_job_id IS NOT NULL`）

**踩坑：PG INT4/INT8 类型不匹配。**
- `INTEGER` 在 PG 是 INT4（i32），但 Rust 读 `Option<i64>` → `ColumnDecode mismatched types`
- 发现模式：NULL 值能解码（`Option<i64>` 对 NULL→None 跳过类型检查），非 NULL 值才报错
- 修复：`reserve_budget` 读 `Option<i32>`→`map(i64::from)`；`get_budget_owner` 同；测试 `cents_delta` 读 `i32`
- 这是 PG mirror 测试再次揪出 SQLite 无类型环境掩盖的 bug（继 Phase 7 timestamptz/INT4→bigint 之后）

**测试修复（2 个错误断言）：**
- "reserve 等于 remaining" 预期错误——设计 `remaining >= amount` → 允许（余额变 0），下一条才 Exhausted。修正 3 处断言（reserve_cas_atomicity/refund_restores_budget/set_owner_budget_overwrite）
