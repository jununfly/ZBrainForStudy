## 1-8 forget 完成 + facts_fence 管道符往返 bug 修复 (completed this session)

- **`forget.rs` 已 port（markdown-first fence-rewrite，v0.32.2 contract）**：原 Rust `forget_fact` op 只有 `expire_fact` 退化路径（TS 在 v0.32.2 已升级为 fence 优先以让遗忘 survive `zbrain rebuild`）。现 `forget_fact_in_fence(engine: &dyn BrainEngine, ...)` 走：lookup 行（需 v51 列 row_num+source_markdown_slug+entity_slug）→ lookup source.local_path → `plan_forget` 纯路由决策（NotFound/AlreadyExpired/Legacy/Fence）→ Fence 路径：page_lock 内 `apply_fence_rewrite`（read→`rewrite_fence_for_forget` 删 claim+set valid_until+append `forgotten: <reason>`→原子写 .tmp→reparse 校验→rename）→ `forget_stamp`；任一失败 best-effort 回退 `expire_fact` legacy。`is_unsupported` 捕获 InMemoryEngine 的 `execute_raw` 默认 "Unsupported" 错误走 legacy。
- **`page_lock.rs` 新增**：`page_lock_for(slug) -> Arc<Mutex<()>>` 进程内每页锁（序列化同 slug 的 fence 写）。**不要**用闭包式 `with_page_lock(f: FnOnce()->Fut)` helper——见下 E0521 陷阱。
- **共享 bug 修复 `facts_fence::parse_row_cells`**：原裸 `inner.split('|')` 不尊重 `escape_fence_cell` 的 `\|` 转义，导致 context 含管道符（forget 追加 `forgotten: <reason>` 必含 `|`）在 render+reparse 往返错位。改为仅在**未转义** `|` 分列并反向 unescape `\|`→`|`（与 `escape_fence_cell` 对称）。这是 1-8 范围内真实缺陷。
- **E0521 陷阱（关键，可复用）**：① 不能在一个 `async fn` 内 `await` 一个「future 带局部生命周期参数」的 helper（`with_page_lock<'s, F, Fut, T> where Fut: 's`）——局部 `'s` 泄漏进外层返回的 future，编译器被迫要求 `'static`，报 "borrowed data escapes outside of method"。改法：直接 `page_lock_for(slug)` 拿 `Arc<Mutex>` 后在调用方持有 guard 做 read-modify-write。② 泛型 `forget_fact_in_fence<'a, B: ForgetBackend + ?Sized + 'a>` 因 `dyn BrainEngine` trait object 默认 `'static`，传 `&'life1 dyn BrainEngine` 时 `'life1: 'static` 冲突。改法：**去掉 `ForgetBackend` async_trait trait 抽象 + 泛型**，直接收 `&dyn BrainEngine` 调原生 `execute_raw`/`expire_fact`（与 `consolidate.rs` 同构）。
