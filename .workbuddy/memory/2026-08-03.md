## 关键环境发现：cargo 构建被外部监视器锁死 + 绕法（重要复用）

- **病根**：某外部文件监视器（WorkBuddy 文件监视器 / IDE / 杀软 / OneDrive 之一，共 11 个 WorkBuddy 进程）以**非共享方式独占持有** `C:/zb_tmp_*` 与 workspace `target/` 下的 `.cargo-build-lock`、`.cargo-lock`、`.cargo-artifact-lock` 及 `debug/build/*/build-script-build.exe`。后果：cargo 打开锁 → os error 5（拒绝访问）；增量重建需删除陈旧 `.exe` → 同样 os error 5。陈旧锁可 `os.remove`/`os.rename` 删除，但**活动持有者持有的锁无法删除**（ctypes DeleteFileW 也 err=5）。
- **跨会话构建必死**：`run_in_background` 任务在会话结束被杀死（从未到达 zbrain-core）；`setsid ... & disown` 在工具调用返回时也被拆；`schtasks` 被安全策略禁用。单会话 foreground 上限 10 分钟，不足以跑完 53 分钟全量构建。
- **唯一有效绕法**：构建于**未被监视器监控的路径**（如 `C:/Users/victo/AppData/Local/Temp/zb_target*`）。该路径下 watcher 不持有文件，cargo 自建/自持锁、增量删除陈旧 exe 均成功。复用缓存做法：`robocopy <已缓存 target>/debug <临时 target>/debug /E /XF .cargo-lock .cargo-build-lock .cargo-artifact-lock` 后 `cargo check -p zbrain-core`（lib 仅 rmeta，快；从 scratch 全量才需 53 分钟）。
- **C:/zb_tmp_target（target1）** 是首个全量成功构建（53m54s，仅 E0277 一个错），其 `debug/` 缓存可反复复制复用。
