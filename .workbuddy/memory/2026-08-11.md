## 损坏 zbrain 仓库彻底重建（根除 missing tree 0e0d0a2d）
- 用户诉求："修复过几次了，最好这次是最后一次"。目标：清理/重建损坏旧 `zbrain`（坏对象 `0e0d0a2d` missing tree，使 `git gc`/`repack` 报错）。
- 两个关键坑（先后撞上）：
  1. **IDE 锁根目录**：WorkBuddy 把 `zbrain` 当活动工作区根，锁住它 → `mv`/`rm -rf` 整个 `zbrain` 报 `Device or resource busy`(EBUSY)；`rm -rf` 还会被安全删除(genie-trash)拦截并在 abort 前把 `.git` 及部分根文件挪进回收站，留下"无 .git、缺 AGENTS.md/Cargo.toml/crates"的残工作树。
  2. **git 原生 Windows 二进制不认 POSIX 路径**：`git -C /c/workspace/...` 与 `git clone --local /c/...` 报 "No such file or directory"（同目录 `ls`/`cp` 正常）。必须用 `cd` 进目录再 `git`。
- **最终成功的就地重建法（不动被锁根目录名、不删根）**：
  1. 先保全独有未跟踪内容：`zbrain/.tmp_ts_src/`（6 个 TS 迁移参考源 + test_build.log）→ 备份到 `C:/Users/victo/AppData/Local/Temp/zb_tmp_ts_src_backup`（sha 校验一致）。
  2. `cp -a zbrain-clean/.git zbrain/.git`（MSYS `cp` 创建子目录不受根锁影响；zbrain-clean 的 origin 本就是 github，复制后 remote 自动正确）。
  3. `cd zbrain && git reset --hard HEAD` → 还原全部 920 个受控文件到 `4ad5291c`。
  4. `git fsck --full`（exit 0，零 missing）+ `git gc --prune=now`（exit 0，**原 missing tree 不再出现**）= 决定性健康证明。
  5. 还原 `.tmp_ts_src/` 到 zbrain（reset --hard 不碰未跟踪文件，已在）。
- 验证：zbrain 与 zbrain-clean HEAD 完全一致 `4ad5291c`；status 仅 `?? .tmp_ts_src/`；`.tmp_ts_src` 7 文件完好。
- 结论：坏对象已从对象库剔除（rebuild 出的 .git 不含它），损坏根除。回收站里被 genie-trash 挪走的旧 .git 碎片可手动清空，无害。
