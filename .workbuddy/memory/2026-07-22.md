## 1-6-7-13 grill 决策树（zj-grill-me + zj-roadmap-driven）

### 探索地基（关键事实）
- TS `sync.ts` 2616 行，用 `execFileSync('git', …)` 直接 shell-out，workspace 无 git2/gix。
- TS `sync_brain` op (operations.ts:2003) → `performSync(ctx.engine, …)`；Rust 侧仅 `SyncStatusOperation`，无 `SyncBrainOperation`。
- **TS sync_brain 只 git PULL 不 PUSH**：pull 遇 detached HEAD / no origin / remote diverged 非致命回退到本地状态并告警。PUSH 属 `zbrain sources federate`（联邦命令，独立 surface）。原 13-3 标签"git push+冲突"语义偏差，已校正为 pull 边界 fallback + 锁。

### 7 个决策（全按推荐答案）
1. **交付策略** = 真·增量 Rust 端口（sync 做 Rust op，ingest 半复用既有 engine 方法，只新写 git shell-out + 编排 + 元数据）。
2. **Git 后端** = shell-out 调 git CLI（`tokio::process::Command`），零新依赖，对齐 TS。
3. **git 封装位置** = `zbrain-core/src/git.rs`（薄 Git 客户端 struct），不放新 crate / 不放 zbrain-cli。
4. **并发锁** = advisory 文件锁（source local_path 下 `.zbrain-sync.lock`，Drop 释放，跨进程，OS 退出自动释放）。不用 in-memory Mutex / DB 标志位。
5. **13-1 首刀** = 抽可复用 `ingest_file(path, source_id, engine)` 助手 + happy-path sync（git pull → 循环 ingest → 更新 last_commit/last_sync_at）。
6. **13-3 范围** = pull 边界 fallback + 文件锁接入 syncOneSource 生命周期，不做 push。
7. **测试** = 真实 git 集成测试（tempfile 临时 repo + InMemory engine 断言），不为测试抽 GitClient trait。
