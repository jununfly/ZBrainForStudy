### 关键决策点

- **Eager-open vs lazy-open**：选 eager open（构造时打开文件），让 open 失败立刻可见而非延迟到首次 `record`（热路径出问题）。代价：从未使用的 writer 也会持 file handle——通过 `new(None)` 解决（无 path = 无 handle）。
- **JSONL per-event vs TS bucket/flush**：放弃 60s/100call batch + on-exit drain（TS 担心 60s bucket 在 hard crash 时丢失），per-event append O(1) write 一次 syscall，最大丢 1 event vs TS 最大丢 60s bucket。**简化胜过性能微优化**：per-event JSONL 在 O(1) 写 100 行 ≤ 1ms，TS bucket 50ms+ flush latency 优化收益有限。
- **TS `search_telemetry` Postgres/PGLite 表** vs Rust JSONL 文件：表的好处是跨进程聚合；JSONL 的好处是零基建（无 migration、无 pgvector、无 pglite 装）+ `tail -f search.jsonl` 可观测。G72 描述"纯本地文件 IO"明确选 JSONL。
- **CLI `--stats` vs 新 subcommand** `zbrain search stats`：选 `--stats` flag 走 `zbrain query` 分支短路径，不引入新 subcommand（clap 派发 + tests 维护成本），且 query/search 共享 `QueryArgs` 已经支持 `--explain` 同型模式。
- **query 字段改 Optional + `conflicts_with_all`**：clap `Option<String>` + `conflicts_with_all` 让 `--stats` 与 search 字段互斥，但不与位置参数 `query` 互斥（query 是位置参数不是 named）。query 缺失时 `run_query_command` 走 stats 短路径 + 错误消息明示。
- **新 `telemetry_writer: Option<Arc<...>>` 字段** 与 `embedding`/`rerank`/`chat_provider`/`mount_resolver` 同 `#[serde(skip)]` Arc 注入模式，CLI 启动时构造 + `with_telemetry_writer` 注入 ctx。
