### 关键决策点

- **Eager-open vs lazy-open**：选 eager open（构造时打开文件），让 open 失败立刻可见而非延迟到首次 `record`（热路径出问题）。代价：从未使用的 writer 也会持 file handle——通过 `new(None)` 解决（无 path = 无 handle）。
- **JSONL per-event vs TS bucket/flush**：放弃 60s/100call batch + on-exit drain（TS 担心 60s bucket 在 hard crash 时丢失），per-event append O(1) write 一次 syscall，最大丢 1 event vs TS 最大丢 60s bucket。**简化胜过性能微优化**：per-event JSONL 在 O(1) 写 100 行 ≤ 1ms，TS bucket 50ms+ flush latency 优化收益有限。
- **TS `search_telemetry` Postgres/PGLite 表** vs Rust JSONL 文件：表的好处是跨进程聚合；JSONL 的好处是零基建（无 migration、无 pgvector、无 pglite 装）+ `tail -f search.jsonl` 可观测。G72 描述"纯本地文件 IO"明确选 JSONL。
- **CLI `--stats` vs 新 subcommand** `zbrain search stats`：选 `--stats` flag 走 `zbrain query` 分支短路径，不引入新 subcommand（clap 派发 + tests 维护成本），且 query/search 共享 `QueryArgs` 已经支持 `--explain` 同型模式。
- **query 字段改 Optional + `conflicts_with_all`**：clap `Option<String>` + `conflicts_with_all` 让 `--stats` 与 search 字段互斥，但不与位置参数 `query` 互斥（query 是位置参数不是 named）。query 缺失时 `run_query_command` 走 stats 短路径 + 错误消息明示。
- **新 `telemetry_writer: Option<Arc<...>>` 字段** 与 `embedding`/`rerank`/`chat_provider`/`mount_resolver` 同 `#[serde(skip)]` Arc 注入模式，CLI 启动时构造 + `with_telemetry_writer` 注入 ctx。

## git stash 灾难（19:00-19:05 GMT+8，HEAD orphan + 二次灾难）

执行 `git stash push -m "WIP: legacy gbrain retire" -- $(cat /tmp/deleted_files.txt)` 时，**直接命中 MEMORY.md "git stash 灾难"铁律的完整 chain**：

1. `git stash` 写入 commit 对象到 `.git/objects/`
2. **sandbox 限制**让 stash 内部 ref transaction 失败（`fatal: cd0f139ee8cfca7ce90a5d565139f3fa6865c01c is not a valid object`）
3. `.git/refs/heads/` 整个目录被 git 失败 cleanup 时删了（sandbox 允许 `.git/` 内文件删除）
4. HEAD → orphan，git status 报 "No commits yet"
5. 试图用 `git reset HEAD` 拆 staging → MEMORY.md 警告过此操作在 orphan HEAD 下解析到 `stash@0`（第二个 stash），**不敢用**

**按 MEMORY.md "若已发生" 铁律修复**：
1. `git fetch origin rust-rewrite --force` 拉回 ref（fetch 只更新 `FETCH_HEAD`，不会自动写 `refs/heads/*`，因为本地 ref 已不在）
2. 对象 store 被 sandbox 清了，**第一次 fetch 后 `git cat-file -t 3705ede2...` 仍 "could not get object info"** —— 第二次 fetch 才有对象
3. `mkdir -p .git/refs/heads .git/refs/remotes/origin .git/refs/tags` 重建 ref 目录
4. `git symbolic-ref HEAD refs/heads/rust-rewrite` 重建 HEAD symbolic ref
5. `git update-ref refs/heads/rust-rewrite 3705ede22a36badd0d9a1fd5c12d5f5b9179098e` 重新挂 ref
6. 验证：`git rev-parse HEAD` = `3705ede2...` ✓，`git status` 回到 "Changes not staged for commit" ✓

**结论（重要，铁律级别）**：

> **此沙箱禁用 `git stash`**。每次 stash 失败都打飞 `.git/refs/`，需手工 `mkdir + symbolic-ref + update-ref` 重建，且需要**两次 fetch**（sandbox 一次性清空 objects）。后续"暂存未提交改动"需求须改用：
> - 写 untracked 描述文件（`docs/plans/YYYY-MM-DD-pending.md`）
> - `git tag backup/<desc>` 保存当前 HEAD（最稳）—— 但孤儿 ref 问题仍要先修
> - 直接 commit（哪怕是 WIP）：sandbox 不会打飞 commit 对象（fetch 验证过对象持久）

**MEMORY.md 待更新**：把"禁用 git stash"和"沙箱对 .git/refs/* 删除无防护"加入铁律章节。
