## ZBRAIN_HOME 跨平台 home 解析统一（commit 5736fe1）

- **根因（承接 G37 陷阱）**：`dirs::home_dir()` 在 Windows 忽略 `$HOME`，只认 `%USERPROFILE%`。Rust 二进制里所有 `~/.zbrain` 解析点若用 `dirs::home_dir()` 或 `env::var("HOME")`，Windows 下 `$HOME` 隔离无效，冒烟误写真实 db。
- **方案**：新增**单一 SSOT** `zbrain_core::paths::{home_root, zbrain_home}`，解析顺序 `ZBRAIN_HOME`（显式跨平台覆盖，值为 home root，故 `~/.zbrain` 落在 `<ZBRAIN_HOME>/.zbrain`）→ `$HOME`（Unix）→ `%USERPROFILE%`（Windows）。全仓库 `~/.zbrain` 解析点统一委托它：
  - `zbrain-cli`：`config::home_root/zbrain_home`（委托 core）、`lib.rs` 9 处 `dirs::home_dir()?.join(".zbrain")` → `config::zbrain_home()`、`resolve_database_path` 的 `~` 展开用 `config::home_root()`、`schema_cmd.rs` user_pack_dir。
  - `zbrain-core/schema_pack`：activate/candidate_audit/discovery/mutate/mutate_audit/pack_lock 共 6 处（原 `env::var("HOME").or_else(USERPROFILE)`）全部改 `crate::paths::zbrain_home()`。删除了原 `schema_pack/paths.rs`，改由顶层 `crate::paths` 承载。
  - `zbrain-worker/supervisor.rs`：pid_file 改 `zbrain_core::paths::zbrain_home()`（删 `dirs_next` 辅助函数）。
- **例外（故意保留）**：daemon 安装路径（launchd/systemd plist/systemd unit 的 home 嵌入）仍用 `dirs::home_dir()`——host 级安装必须落在真实 OS home，隔离 ZBRAIN_HOME 在此无意义；已在 `lib.rs` run_autopilot_command 处注释说明。
- **测试**：`zbrain_core::paths` 单元测（非变异 env，避免与 schema_pack 单线测试竞态；仅当 `ZBRAIN_HOME` 已在环境存在时断言）。全量 green：schema_pack 188、worker supervisor 10、cli config 27、paths 1。
- **E2E 真验**：`ZBRAIN_HOME=/c/tmp/zbrain-e2e zbrain schema use zbrain-base` → debug 追踪确认 `write_home_config path = /c/tmp/zbrain-e2e/.zbrain/config.json`（ZBRAIN_HOME 生效）；`<ZBRAIN_HOME>/.zbrain` 与真实 `~/.zbrain` 互不干扰。
- **结论**：现在 `ZBRAIN_HOME=/tmp/x zbrain ...` 在 Linux/Windows **均重定向全部 `~/.zbrain` 状态**，取代失效的 `$HOME` 隔离，成为推荐的冒烟/隔离机制。旧“只能靠 `-c` 或 `USERPROFILE`”的限制已解除。
